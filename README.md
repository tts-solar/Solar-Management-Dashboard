# Solar Management Dashboard

แดชบอร์ดติดตามผลผลิตไฟฟ้าโซลาร์ของแต่ละ Plant — ผลผลิตเทียบแผน, Efficiency, สัดส่วนที่โซลาร์ช่วยลดค่าไฟ, จุดคุ้มทุน (BEP) และตารางข้อมูลรายวัน/รายเดือน

## มี 2 แบบ — ใช้แบบไหน

ทั้งสองแบบเป็นแอปเดียวกัน ความสามารถเท่ากัน **เริ่มต้นว่างเปล่าเหมือนกัน (ไม่มีข้อมูลติดมาในไฟล์)** และนำเข้าไฟล์ของคุณเองได้ทั้งคู่ ต่างกันแค่วิธีเปิดและสิ่งที่ติดมาเพิ่ม

| | เวอร์ชันเว็บ (ออนไลน์) | แอป Offline |
|---|---|---|
| เปิดที่ไหน | https://tts-solar.github.io/Solar-Management-Dashboard/ | ไฟล์ `solar-dashboard-offline.html` ในเครื่อง |
| เหมาะกับ | ลองใช้ครั้งแรก / แจกไฟล์ Offline ให้คนอื่น | ใช้งานจริงกับข้อมูลของ Plant คุณเอง |
| ต้องใช้อินเทอร์เน็ต | ใช่ (แค่ตอนเปิดหน้าเว็บ) | ไม่ต้องเลย |
| นำเข้าไฟล์ | ได้ | ได้ |
| ปุ่มที่มีเพิ่ม | **Blank Offline Copy** — โหลดไฟล์ Offline เปล่าไปแจก | — |
| แอปจำข้อมูลไว้ที่ไหน | เบราว์เซอร์ที่เปิดเว็บนี้ (ที่เดียวรวมกัน) | เบราว์เซอร์เครื่องนั้น แยกตามที่อยู่ของไฟล์ |

> **ข้อมูลไม่เคยถูกส่งออกจากเบราว์เซอร์ ทั้งสองแบบ** — ทั้ง 2 build ถูกล็อกด้วย Content-Security-Policy ไม่ให้ต่ออินเทอร์เน็ตเลย ไฟล์ที่นำเข้าถูกอ่านและคำนวณในหน้าเว็บล้วนๆ
>
> แต่ยังคง **แนะนำให้ใช้แอป Offline กับข้อมูลจริง** — ทำงานได้โดยไม่ต้องมีเน็ต และแต่ละไฟล์แยกข้อมูลกันชัดเจน
>
> **ห้าม commit ข้อมูลจริงขึ้น repo นี้เด็ดขาด** — repo และเว็บเป็นสาธารณะ

## ใช้แอป Offline

1. **ดาวน์โหลด** — เปิดเวอร์ชันเว็บ แล้วกดปุ่ม **Blank Offline Copy** ที่แถบเมนูด้านซ้าย (หรือโหลดตรงที่ https://tts-solar.github.io/Solar-Management-Dashboard/solar-dashboard-offline.html)
   - ได้ไฟล์ `solar-dashboard-offline.html` เป็นไฟล์เปล่า ไม่มีข้อมูลใดๆ อยู่ข้างใน
2. **เปิด** — ดับเบิลคลิกไฟล์ จะเปิดในเบราว์เซอร์ ขึ้นหน้า "เริ่มใช้งาน Solar Dashboard (Offline)"
3. **นำเข้าไฟล์** — กดปุ่ม **Import Data** ที่แถบเมนูด้านซ้าย หรือลากไฟล์มาวางบนหน้า เลือกหลายไฟล์พร้อมกันได้ (1 ไฟล์ = 1 Plant)
   - รองรับ CSV ราย 15 นาที และรายงานรายเดือน (Excel `.xlsx` หรือ CSV) — ดูรายละเอียดหัวข้อถัดไป
   - ชื่อ Plant มาจากชื่อไฟล์ ดูหัวข้อ "รูปแบบไฟล์ที่นำเข้าได้"
   - ระบบจะแสดงสรุปสิ่งที่อ่านได้ให้ดูก่อน แล้วค่อยกด **ยืนยันนำเข้า**
   - **นำเข้าไฟล์ของ Plant เดิมซ้ำ = รวมข้อมูล ไม่ใช่แทนที่** — วันที่ที่มีอยู่แล้วจะถูกเก็บไว้ตามเดิม เพิ่มเฉพาะวันที่ใหม่เท่านั้น (ใช้ต่อข้อมูลหลายไฟล์เป็นช่วงยาวได้)
4. **ตั้งค่า** — กดปุ่ม **Plant Settings** เพื่อใส่ข้อมูล Plant (ชื่อ, วันเริ่มใช้งาน, ขนาดติดตั้ง kWp, ค่าไฟ, เงินลงทุน ฯลฯ)
   - ช่องที่เว้นว่างจะใช้ค่าเริ่มต้นหรือค่าที่คำนวณอัตโนมัติ (ตัวเลขสีเทาในช่อง)
   - กระดิ่งมุมขวาบนจะบอกว่า Plant ไหนยังกรอกข้อมูลสำคัญไม่ครบ คลิกแล้วกระโดดไปที่ช่องนั้นได้เลย
5. **ดูข้อมูล** — คลิกชื่อ Plant หรือแถวในตาราง เพื่อเจาะดูรายปี → รายเดือน
   - ตัวกรองมุมขวาบน: เลือก **ปี/เดือน** หรือ **ช่วงวัน** และสลับดูเฉพาะ **กลางวัน / ทั้งวัน / กลางคืน**
   - ตัวกรอง "ช่วงวัน" และ "กลางวัน/กลางคืน" จะขึ้นเฉพาะเมื่อข้อมูลละเอียดพอ (นำเข้าจาก CSV ราย 15 นาที) — ข้อมูลรายเดือนจะไม่มีให้เลือก
6. **แอปจำข้อมูลให้อัตโนมัติ** — เมื่อนำเข้าแล้ว แอปจะจำข้อมูลไว้ในเบราว์เซอร์เครื่องนี้เอง เปิดไฟล์เดิมครั้งหน้าก็เห็นข้อมูลเดิมทันที ไม่ต้องนำเข้าใหม่และไม่ต้องกดบันทึก
   - ปุ่ม **Clear Data** ลบข้อมูลที่จำไว้ในเบราว์เซอร์นี้ทิ้ง — **ถ้าใช้เครื่องร่วมกับคนอื่น ให้กดล้างข้อมูลก่อนเลิกใช้**
   - ไฟล์ Offline แต่ละไฟล์ (คนละที่อยู่หรือคนละชื่อ) แยกข้อมูลกัน ไม่ปนกัน
7. **บันทึกไฟล์ (สำเนาพกพา)** — กดปุ่ม **Save File** จะได้ไฟล์ HTML ใหม่ (`solar-dashboard-ปี-เดือน-วัน.html`) ที่มีข้อมูลและค่าที่ตั้งไว้ฝังอยู่ข้างใน เอาไปเปิดบนเครื่องอื่นได้เลย
8. **ออกรายงาน** — **Export Report** (รายงานประหยัดค่าไฟรายเดือน/รายปี) และ **Report PDF** (ภาพแดชบอร์ดจริงสำหรับพิมพ์)

### ไฟล์ที่บันทึกแล้วมีข้อมูลจริงอยู่ข้างใน

- เก็บไว้ในเครื่อง หรือส่งให้เฉพาะคนที่ควรเห็นข้อมูลนั้นเท่านั้น
- ห้ามอัปโหลดขึ้นเว็บ, ห้ามใส่ใน repo นี้, ห้ามแชร์ในที่สาธารณะ

## รูปแบบไฟล์ที่นำเข้าได้

ไม่มีไฟล์จากพอร์ทัล? ในหน้านำเข้ามีปุ่มดาวน์โหลด **เทมเพลตรายเดือน (CSV)** และ **ตัวอย่างรายวัน (CSV)** ให้กรอกเอง (อย่าลืมเปลี่ยนชื่อไฟล์เป็นชื่อ Plant ก่อนนำเข้า)

### 1. CSV ราย 15 นาที (ไฟล์ export จากระบบ monitor)

```csv
Date/Time,Energy Produced (Wh),Energy Consumed (Wh),Exported to Grid (Wh),Imported from Grid (Wh)
12/01/2025 00:00,-6,2215,0,2215
12/01/2025 00:15,-6,2280,0,2280
```

- ชื่อ Plant = ข้อความก่อนเครื่องหมาย `_` ในชื่อไฟล์ เช่น `AB_ข้อมูล 6 เดือน.csv` → Plant `AB`
- คอลัมน์ที่ต้องมี: `Date/Time` และ `Energy Produced` · คอลัมน์เสริม: `Energy Consumed`, `Exported to Grid`, `Imported from Grid`
- วันที่เป็น `เดือน/วัน/ปี ชั่วโมง:นาที` (MM/DD/YYYY HH:mm) หรือ `YYYY-MM-DD HH:mm`
- **หน่วยอ่านจากหัวคอลัมน์** — มี `kWh` หรือ `MWh` จะแปลงให้ **ถ้าหัวคอลัมน์ไม่ระบุหน่วยเลย ระบบถือว่าเป็น Wh** (ตามที่พอร์ทัลส่งออก)
- ช่วงเวลาอื่นที่ไม่ใช่ 15 นาทีก็ได้ — ระบบหาช่วงห่างที่พบบ่อยที่สุดเอง
- รองรับไฟล์ UTF-8 และ Windows-874 (Excel ภาษาไทยรุ่นเก่า)
- แถวที่อ่านไม่ได้จะถูกข้าม และแจ้งจำนวนให้ทราบ

### 2. รายงานรายเดือน "Plant Report" (Excel `.xlsx` หรือ CSV)

```csv
Plant Report - ตัวอย่าง 2026
Statistical Period,PV Yield (kWh),Consumption (kWh),Export (kWh),Import (kWh),Peak Power (kW)
2026-01,1250.5,320.0,980.2,50.1,8.4
```

- ชื่อ Plant มาจากชื่อไฟล์ โดยตัดคำว่า "Plant Report" และปีออก เช่น `Plant Report - SC Tower 2024.xlsx` → Plant `SC Tower`
- คอลัมน์ที่ใช้: `Statistical Period` (YYYY-MM), `PV Yield` → ผลิต, `Consumption` → ใช้ไฟ, `Export` → ขายไฟ, `Import` → ซื้อไฟ, `Peak Power` → กำลังสูงสุด
- **หน่วยเริ่มต้นของรายงานรายเดือนคือ kWh** (ต่างจาก CSV ราย 15 นาที) ระบุ `Wh` หรือ `MWh` ในหัวคอลัมน์เพื่อแปลง
- ข้อมูลเป็นระดับรายเดือน — กราฟรายเดือน/รายปีแม่นยำ ส่วนมุมมองรายวันจะเห็นหนึ่งจุดต่อเดือน (ตามความละเอียดของรายงาน) และตัวกรอง "ช่วงวัน" จะไม่ขึ้นให้
- นำเข้าหลายปีพร้อมกันได้ ระบบรวมเป็น Plant เดียวกันให้อัตโนมัติ

## ความเป็นส่วนตัว

| ป้องกันอะไร | ทำอย่างไร |
|---|---|
| ข้อมูลจริงหลุดออกจากเบราว์เซอร์ | **ทั้ง 2 build** ถูกล็อกไม่ให้ต่ออินเทอร์เน็ต (Content-Security-Policy `connect-src 'none'`) ทุกอย่างรวมอยู่ในไฟล์เดียว ไม่มีการเรียกออกไปข้างนอกเลย |
| ข้อมูลจริงถูก build ติดเข้าไปในไฟล์ที่เผยแพร่ | `bundledDataGuard` + `cssSourceGuard` ใน `vite.config.ts` ตรวจทุกโมดูลที่ Vite resolve จริง — มีอะไรนอก allowlist หลุดเข้ามา build ล้มทันที |
| ข้อมูลจริงขึ้น repo | `.gitignore` กันโฟลเดอร์ `data/` (ยกเว้น `data/sample-*.csv`), โฟลเดอร์ `ข้อมูล/`, ไฟล์ Excel และไฟล์ที่บันทึกจากแอป |
| ข้อมูลค้างในเครื่องที่ใช้ร่วมกัน | แอปจำข้อมูลไว้ในเบราว์เซอร์เครื่องนั้น — กดปุ่ม **Clear Data** เพื่อลบทิ้งก่อนส่งเครื่องต่อ (ไฟล์แต่ละไฟล์แยกข้อมูลกันด้วยที่อยู่ไฟล์) |
| พลาดทั้งหมดข้างบน | `npm run build` จบด้วยตัวตรวจ `tools/privacy-check.mjs` — ถ้าพบข้อมูลที่ไม่ใช่ตัวอย่างใน git หรือในไฟล์ที่จะเผยแพร่ build จะล้มและไม่มีอะไรถูกเผยแพร่ |

ก่อน commit ตรวจทุกครั้ง: `git status` ต้องไม่มีไฟล์ข้อมูลจริง

## สำหรับนักพัฒนา

ต้องใช้ Node.js 22

```bash
npm ci               # ติดตั้ง
npm run dev          # เปิดเครื่องมือพัฒนา แบบเวอร์ชันเว็บ
npm run dev:offline  # เปิดเครื่องมือพัฒนา แบบแอป Offline
npm test             # รันเทสต์
npm run build        # สร้าง 2 ไฟล์ใน dist/ แล้วตรวจความเป็นส่วนตัว
```

`npm run build` ได้ไฟล์เดียวจบ (รวม JS/CSS/ฟอนต์) 2 ไฟล์ — **ทั้งคู่ไม่มีข้อมูลอยู่ข้างใน**:

- `dist/solar-dashboard-offline.html` — แอป Offline เปล่า (build ก่อน)
- `dist/index.html` — เวอร์ชันเว็บ ซึ่งฝังไฟล์ Offline ข้างบนไว้แบบ base64 เพื่อให้ปุ่ม **Blank Offline Copy** แจกไฟล์ได้โดยไม่ต้องต่อเน็ต (จึงมีขนาดใหญ่กว่า)

`data/sample-MH.csv` เป็นข้อมูลสังเคราะห์ ใช้เป็น fixture ของเทสต์และเป็นลายนิ้วมือให้ `privacy-check` ตรวจว่าไฟล์ที่เผยแพร่ไม่มีข้อมูลติดไป — **ไม่ได้ถูก bundle เข้าแอป**

Stack: Vite + TypeScript + Chart.js (vite-plugin-singlefile) — dependency ตอน runtime มีแค่ 3 ตัว การอ่าน `.xlsx` เขียนเองใน `src/data/xlsx.ts` โดยใช้ `DecompressionStream` ของเบราว์เซอร์ ไม่ง้อ library

### Deploy

push ขึ้น branch `main` แล้ว GitHub Actions (`.github/workflows/deploy.yml`) จะรันเทสต์ build ตรวจความเป็นส่วนตัว แล้วเผยแพร่ทั้ง 2 ไฟล์ขึ้น GitHub Pages ให้อัตโนมัติ — ถ้าขั้นใดล้ม จะไม่มีอะไรถูกเผยแพร่

ตั้งค่าครั้งแรก: GitHub repo → **Settings → Pages → Source: GitHub Actions**
